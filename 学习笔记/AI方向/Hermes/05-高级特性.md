除了基本对话和消息接入，Hermes 还藏了一堆好东西。这篇把用得上的高级功能过一遍——有些我天天用，有些知道就行。

## 子代理（Subagent）——把活儿分出去

Subagent 是我用次数最多的高级功能。说人话就是：**主 Agent 忙不过来时，可以招几个临时工帮忙干**。

```yaml
delegation:
  max_concurrent_children: 3    # 默认3个并发
  max_spawn_depth: 1            # 嵌套深度（1=只能叶子，2=可再委派）
  orchestrator_enabled: false   # 是否允许编排者模式
```

### 怎么用

```python
# 一个任务
delegate_task(
    goal="分析代码库结构",
    context="项目在 /path/to/project",
    toolsets=["terminal", "file"]
)

# 多个任务并行
delegate_task(tasks=[
    {"goal": "检查后端 API", "toolsets": ["terminal"]},
    {"goal": "检查前端代码", "toolsets": ["terminal", "file"]},
])
```

> [!tip] 默认 3 个并发够用吗？
> 大多数时候够。要批量爬 20 个页面时才觉得少——把 `max_concurrent_children` 改到 5-8 就行，别一下子拉太高，CPU 扛不住。

### 两种角色

| 角色 | 能干啥 |
|------|--------|
| `leaf`（临时工） | 调用工具干活，不能再招人 |
| `orchestrator`（包工头） | 自己还能再往下委派 |

### 内部实现

Subagent 不是独立进程，也不是网络调用——**就是同一个 Python 进程里开了个新线程**。

- ✅ **开销极低** — 毫秒级创建
- ✅ **共享资源** — 凭证、文件系统直接用
- ⚠️ **不隔离** — 一个崩了理论上影响全局

> [!tip] 跟 Claude Code 的 ACP 模式不一样
> Hermes 的 Subagent 默认走线程；如果指定 `acp_command="claude"`，才启动独立子进程走 stdin/stdout 的 JSON-RPC 通讯——隔离性更好但开销大。

### ACP 模式

```python
delegate_task(
    goal="写一个 React 组件",
    acp_command="claude",        # 启动 Claude Code
    acp_args=["--acp", "--stdio"]
)
```

支持：Claude Code、OpenCode、Codex。

## 定时任务（Cron）——让它自己干活

Hermes 内置了调度器，不需要再装 cron、systemd timer 那一套。

```yaml
cron:
  enabled: true
  jobs:
    # ── 每天早上的简报 ──
    morning_brief:
      schedule: "0 8 * * *"
      prompt: "生成今日简报并发送到 Telegram"
      enabled: true
    
    # ── 每30分钟的健康检查 ──
    health_check:
      schedule: "30m"
      prompt: "检查各服务健康状态"
      script: ~/.hermes/scripts/health-check.py
    
    # ── 一次性任务 ──
    one_time_task:
      schedule: "2026-05-01T10:00:00"
      prompt: "执行一次性备份"
      repeat: 1
```

### 链式任务

```yaml
    data_collector:
      schedule: "0 */2 * * *"
      prompt: "收集数据"
    
    data_processor:
      schedule: "30 */2 * * *"
      prompt: "处理数据"
      context_from: ["data_collector"]  # 等上个任务跑完再执行
```

### 调度格式速查

| 格式 | 例子 | 说明 |
|------|------|------|
| 相对时间 | `"30m"`、`"every 2h"` | 简单粗暴，推荐 |
| Cron 表达式 | `"0 8 * * *"` | 标准 Linux 格式 |
| ISO 时间戳 | `"2026-05-01T10:00:00"` | 一次性任务 |

### 管理命令

```bash
hermes cron list       # 看所有任务
hermes cron run <id>   # 手动跑一次（调试用）
hermes cron pause <id> # 暂停
hermes cron resume     # 恢复
```

> [!tip] 调试技巧
> 写 Cron 任务时先用 `hermes cron run <id>` 手动跑一次确认没问题再让它自动跑。不然定时炸了都不知道。

## Browser 自动化——它会上网

内置无头浏览器（Playwright），填表单、抓数据、甚至看验证码都行。

```yaml
tools:
  browser:
    headless: true
    timeout: 30000         # 毫秒
    viewport:
      width: 1280
      height: 720
```

### 可用工具

| 工具 | 功能 |
|------|------|
| `browser_navigate` | 导航到 URL |
| `browser_snapshot` | 获取页面可访问性树 |
| `browser_click` | 点击元素 |
| `browser_type` | 输入文本 |
| `browser_scroll` | 滚动页面 |
| `browser_press` | 按键操作 |
| `browser_vision` | **截图 + 视觉分析**（验证码克星） |
| `browser_get_images` | 列出页面图片 |
| `browser_console` | 控制台输出 / 执行 JS |
| `browser_back` | 返回上一页 |

> [!tip] `browser_vision` 真香
> 遇到验证码、弹窗确认、或者那些截图比解析 DOM 快得多的页面，直接让模型看图比折腾选择器靠谱。

## Code Execution——在代码里调工具

Agent 可以在回答里直接跑 Python，而且代码里还能反手调 Hermes 的工具。

```yaml
tools:
  code_execution:
    enabled: true
    timeout: 300             # 5分钟
    docker:
      enabled: false
      image: "python:3.11"
```

### 代码里能调什么

```python
from hermes_tools import read_file, write_file, search_files, patch, terminal, retry, json_parse, shell_quote

# 文件操作
result = read_file("path/to/file")
write_file("path/to/output", "content")

# 搜索
matches = search_files(pattern="TODO", path=".", file_glob="*.py")

# 编辑
patch(path="file.py", old_string="old", new_string="new")

# 终端
output = terminal("ls -la")

# 工具函数
data = json_parse(raw_text)          # 容错 JSON 解析（遇到过带控制字符的 JSON？它干就是这个）
quoted = shell_quote(user_input)     # shell 安全转义
result = retry(fn, max_attempts=3)   # 重试
```

### 什么时候值得用代码

| 场景 | 为什么用代码而不用直接调工具 |
|------|---------------------------|
| 3+ 连续调用 | 代码里调工具，结果不进上下文窗口 |
| 条件分支 | if/else 比靠 LLM 决策稳定 |
| 循环遍历 | 遍历 N 个文件，代码比 LLM 一个个调快 N 倍 |
| 数据处理 | JSON/CSV 过滤，2 行搞定 |
| 结果过滤 | 工具返回 1MB 数据，代码里先过滤再返回 |

> [!warning] Docker 模式启动慢
> 要等容器启动的时间。除非真的需要隔离环境，不然关掉 Docker 模式跑得更快。

## Hooks——监听 Agent 的一举一动

三层钩子，在 Agent 循环的不同阶段插入自定义脚本：

```yaml
hooks:
  # 1️⃣ 调工具之前
  pre_tool:
    - name: "log-tool"
      command: "echo 'Tool: $TOOL_NAME' >> /tmp/tool.log"
  
  # 2️⃣ 工具结束后
  post_tool:
    - name: "check-output"
      command: "validate_output.py $TOOL_RESULT"
  
  # 3️⃣ 工具出错了
  on_error:
    - name: "notify-admin"
      command: "curl -X POST https://alert.example.com/error"
```

### 内置变量

| 变量 | 含义 |
|------|------|
| `$TOOL_NAME` | 工具名 |
| `$TOOL_INPUT` | 工具输入（JSON） |
| `$TOOL_RESULT` | 工具结果（JSON） |
| `$TOOL_ERROR` | 错误信息 |
| `$SESSION_ID` | 当前会话 ID |

> [!tip] Hooks 最适合做审计
> 如果把 Hermes 开放给团队用，`pre_tool` 记录谁调了什么 + `on_error` 出问题了通知你，两个钩子一搭，出了事能溯源。

## Checkpoints——想回哪步回哪步

> [!quote] 第一次用的时候觉得「不就是存档吗」，直到实验跑崩了回退到半小时前——真香。

```bash
# 存一个
hermes checkpoint save "before-refactor"

# 看看有哪些
hermes checkpoint list

# 读档
hermes checkpoint load "before-refactor"

# 每轮自动存
hermes chat --auto-checkpoint
```

### 配置

```yaml
hermes:
  checkpoint:
    enabled: true
    auto: true            # 每轮自动保存
    dir: ~/.hermes/checkpoints/
    max_count: 10         # 最多保留10个
    compression: true     # 压缩存储
```

## 上下文压缩（Context Compression）

长对话跑着跑着上下文窗口会满。Hermes 可以自动压缩。

```yaml
hermes:
  session:
    compression:
      enabled: true
      strategy: summary    # summary / truncate / smart
      trigger_at: 80000    # 超过 80K tokens 触发
      preserve_first: 10   # 保留前 N 轮对话原文
```

三种策略怎么选：

| 策略 | 行为 | 什么时候选 |
|------|------|-----------|
| `summary` | 早期对话→摘要 | 对话有主线，压缩后还能回忆 |
| `truncate` | 丢最早的部分 | 早期内容不重要了 |
| `smart` | 只压缩不重要部分 | 不想冒险丢重要内容 |

> [!tip] 我选了 smart
> 反正都是自动触发，交给它自己判断比我瞎猜安全。代价是比 summary 多消耗一点 token 来分析哪些重要。
