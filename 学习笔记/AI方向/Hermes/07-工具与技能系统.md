# 🧰 工具与技能系统

Hermes 的扩展能力全靠这三个东西配合：**Tools**（干活的手）、**Skills**（干活的经验）、**Memory**（记事的脑子）。搞懂它们怎么配合，你就知道 Hermes 能干什么、怎么让它干更多。

> [!tip] 一句话区分
> - **Tool** = 一个函数（调 terminal、读文件）
> - **Skill** = 一个工作流程（「发现 Bug → 二分定位 → 修复验证」）
> - **Memory** = 事实数据库（「Frank 时区是 Asia/Shanghai」）

---

## Tools（工具）

工具是 Agent 与外部世界交互的接口。Hermes 内置 **50+ 工具**。

### 工具分类

| 分类 | 工具 | 用途 |
|------|------|------|
| **终端** | `terminal` | 执行 shell 命令 |
| **文件** | `read_file`, `write_file`, `search_files`, `patch` | 文件读写、搜索、编辑 |
| **网络** | `web_search`, `web_fetch` | 联网搜索、抓取 |
| **浏览器** | `browser_navigate`, `browser_click`, `browser_vision` 等 9 个 | 网页自动化 |
| **代码执行** | `execute_code` | 运行 Python（可调 Hermes 工具） |
| **子代理** | `delegate_task` | 委派任务给子 Agent |
| **定时** | `cronjob` | 管理定时任务 |
| **记忆** | `memory` | 读写持久记忆 |
| **技能** | `skill_view`, `skill_manage`, `skills_list` | 技能管理 |
| **会话** | `session_search` | 搜索历史会话 |
| **视觉** | `vision_analyze` | 图片分析 |
| **TTS** | `tts` | 文本转语音 |
| **待办** | `todo` | 任务列表管理 |
| **消息** | `send_message` | 发送消息到平台 |
| **MCP** | (自动发现) | MCP 服务器工具 |
| **其他** | `webhook_subscriptions`, `heartmula` 等 | 专用 |

> [!tip] 不需要记住所有工具
> Agent 自己会选。你只需要知道「Hermes 有能力做这些事」，具体用哪个模型自己决定。

### 工具发现

```yaml
tools:
  auto_discover: true    # 自动加载可用工具
  toolset: default       # 预设工具包
```

### Toolsets（工具包）

| 工具包 | 说明 | 包含工具 |
|--------|------|---------|
| `default` | 标准 | terminal, file, search, web, memory, skills, todo, vision |
| `minimal` | 轻量 | read_file, terminal, web_search |
| `full` | 完整 | 所有工具 |
| `none` | 空 | 无工具 |
| `web` | 只网络 | web_search, web_fetch |
| `terminal` | 只终端 | terminal |
| `file` | 只文件 | read_file, write_file, search_files, patch |
| `search` | 只搜索 | session_search, web_search |

> [!tip] 工具包可以组合
> 比如部署公开服务时用 `minimal` 起步，必要时在代码里临时加 `delegate_task` 权限。比直接上 `full` 安全。

### 自定义工具

放置在 `~/.hermes/tools/`，支持 Python / Shell 脚本：

```python
# ~/.hermes/tools/my_tool.py
def my_tool(param1: str, param2: int = 42) -> dict:
    """工具描述（自动生成 Schema）"""
    result = do_something(param1, param2)
    return {"result": result}
```

> [!tip] 函数签名即文档
> 类型注解 + 文档字符串 = 自动生成 OpenAI 兼容的 tool schema。不需要额外写 JSON 定义。

## Skills（技能）

技能是**可重用的工作流知识**，保存为 SKILL.md 文件。相当于给 Agent 的专用「操作手册」。

### 技能结构

```markdown
---
name: systematic-debugging
description: 系统化调试工作流
---
# 系统化调试

## 触发条件
当遇到 bug、测试失败、或意外行为时。

## 步骤
1. 重现问题（记录环境、输入、输出）
2. 缩小范围（二分法）
3. 检查日志/错误栈
4. 验证假设
5. 修补 + 验证

## 注意事项
- 先确认不是环境问题
- 每次只改一处
```

### 技能存储

```
~/.hermes/skills/
├── systematic-debugging/
│   └── SKILL.md
├── github-pr-workflow/
│   ├── SKILL.md
│   └── references/
│       └── pr-template.md
└── weekly-report/
    ├── SKILL.md
    └── scripts/
        └── generate.py
```

### 技能管理

```bash
# 列出技能
hermes skills list

# 查看技能
hermes skills view systematic-debugging

# 创建
hermes skills create my-skill

# 编辑
hermes skills edit my-skill
```

### 自动匹配

Hermes 会自动加载与当前任务相关的技能：

```yaml
skills:
  enabled: true
  auto_load: true
  matching:
    strategy: semantic      # keyword / semantic / hybrid
    threshold: 0.7
```

> [!tip] 技能匹配不是玄学
> `semantic` 策略把你的问题转成向量，跟技能描述算相似度。超过 `threshold: 0.7` 就自动加载。想让技能更容易被匹配到，把 description 写得精准一点。

### 编写原则

| 原则 | 说明 |
|------|------|
| **触发条件** | 明确什么情况下使用 |
| **步骤化** | 编号可复现的步骤 |
| **命令精确** | 给出准确命令，别猜 |
| **陷阱提示** | 常见错误 + 解决方案 |
| **验证步骤** | 如何确认执行成功 |

## Memory（记忆系统）

跨会话持久记忆，两种类型：

### 用户记忆（User Profile）

```python
memory(action="add", target="user",
    content="用户叫 Frank，偏好用中文交流")
```

保存内容：用户画像、偏好、个人习惯。

### 通用记忆（Memory Notes）

```python
memory(action="add", target="memory",
    content="项目使用 pytest + xdist 并行测试")
```

保存内容：环境事实、项目惯例、工具特性。

### 记忆管理规则

| 要保存的 | 不要保存的 |
|---------|-----------|
| ✅ 用户偏好（名字、时区、风格） | ❌ 任务进度 |
| ✅ 环境事实（OS、工具版本） | ❌ 会话日志 |
| ✅ 项目惯例（测试框架、代码风格） | ❌ 临时 TODO |
| ✅ 纠正记录 | ❌ 明显的信息 |

> [!tip] 什么算「明显的信息」？
> 比如「Python 是一种编程语言」这种就不需要存。存了反而浪费上下文窗口——每次对话都要读一遍，但你早就知道。

### 配置

```yaml
memory:
  enabled: true
  long_term: true
  max_memory_items: 100
  dedup: true
  auto_consolidate: true
  consolidation_threshold: 20
```

## Context Files（上下文文件）

项目根目录的自动发现文件：

| 文件 | 优先级 |
|------|--------|
| `AGENTS.md` | 最高 |
| `CLAUDE.md` | 次高 |
| `.cursorrules` | 第三 |

这些文件会被自动注入 System Prompt，告知 Agent 项目规范。

```yaml
tools:
  auto_discover: true   # 开启自动发现
```

> [!tip] 多文件并存时只生效最高优先级那个
> 如果你在项目根目录同时放了 `AGENTS.md` 和 `CLAUDE.md`，只有 `AGENTS.md` 会被读入。选一个维护就好，不要放两个。
