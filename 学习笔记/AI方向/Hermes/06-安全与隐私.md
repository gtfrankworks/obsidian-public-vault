# 🔐 安全与隐私

Hermes 设计了 **7 层安全防御体系**，涵盖从输入到输出的全链路保护。

---

## 1. 速率限制（Rate Limiting）

防止滥用和 DDoS：

```yaml
gateway:
  rate_limit:
    enabled: true
    max_messages_per_minute: 30
    burst: 10              # 瞬时突发容量
    strategy: sliding_window  # sliding_window / token_bucket / fixed_window
```

按用户/IP/聊天ID 分别统计，超出自动静默。

---

## 2. 内容过滤（Content Filtering）

消息收发双向过滤：

```yaml
gateway:
  content_filter:
    enabled: true
    mode: strict           # off / basic / strict / custom
    
    # 关键词黑名单
    blocked_words:
      - "password="
      - "SECRET_KEY"
    
    # 正则规则
    rules:
      - pattern: "(apikey|token|secret).*[:=]\\s*['\"].+['\"]"
        action: redact     # redact / block / warn
    
    # 白名单
    allowed_patterns:
      - "README.md"
```

### 过滤模式

| 模式 | 行为 |
|------|------|
| `off` | 不过滤 |
| `basic` | 仅拦截已知敏感模式 |
| `strict` | 拦截 + 替换（`***`） |
| `custom` | 自定义规则集 |

---

## 3. 工具沙箱（Tool Sandbox）

工具执行隔离：

```yaml
tools:
  sandbox: strict
```

| 级别 | 终端命令 | 文件操作 | 网络 | 代码执行 |
|------|---------|---------|------|---------|
| `off` | ✅ 无限制 | ✅ 无限制 | ✅ | ✅ |
| `standard` | ⚠️ 阻断高危命令 | ⚠️ 只允许项目目录 | ✅ | ✅ |
| `strict` | ❌ 白名单仅限安全命令 | ❌ 只读 | ❌ | ❌ |

**高危命令拦截列表**（standard+ 模式自动拦截）：
- `rm -rf /`、`dd if=`、`mkfs`、`fdisk`、`chmod -R 777 /`
- 外网连接（curl/wget 到外部 IP）
- 系统服务操作（systemctl、service）

---

## 4. 权限控制（RABC）

基于角色的访问控制：

```yaml
gateway:
  roles:
    admin:
      allowed_commands: ["*"]
      allowed_tools: ["*"]
    
    user:
      allowed_commands: ["terminal", "read_file", "web_search"]
      denied_tools: ["execute_code", "cronjob", "delegate_task"]
    
    readonly:
      allowed_commands: ["read_file", "search_files"]
      denied_tools: ["*"]
```

**权限检查在路由层**，用户发消息 → Gateway 路由 → 检查角色权限 → 放行/拒绝。

---

## 5. 命令黑名单（Deny Commands）

节点级别的命令过滤：

```yaml
gateway:
  nodes:
    deny_commands:
      - "shutdown"
      - "reboot"
      - "poweroff"
```

> ⚠️ **注意：** 这是**命令名精确匹配**，不是内容过滤。想拦截 `rm -rf /` 需要精确配置命令名。

---

## 6. 会话超时与隔离

```yaml
gateway:
  session:
    timeout: 1800           # 30分钟无活动自动清理
    max_concurrent: 50      # 防资源耗尽
    isolated: true           # 不同用户的会话隔离
```

## 7. 审计日志

```yaml
logging:
  level: info
  audit:
    enabled: true
    # 记录所有工具调用
    log_tool_calls: true
    # 记录所有 API 调用（不含实际内容）
    log_api_calls: true
    # 日志文件
    file: ~/.hermes/audit.log
```

## 隐私保护策略

### 本地优先

- 所有数据默认存储在 `~/.hermes/` 目录下
- 不发送遥测数据
- 不收集使用统计
- API Key 存储在本地 `.env` 文件

### 网络隔离

| 场景 | 网络要求 |
|------|---------|
| CLI 对话 | ✅ 需要 API 提供者的网络 |
| 纯本地模型 | ✅ 完全离线 |
| Gateway 消息平台 | ✅ 需要对应平台的网络 |

### 敏感信息处理

自动检测并过滤环境中的敏感信息：

- `api_key`、`secret`、`token`、`password`、`private_key` 等字段
- 配置 `show` 命令自动隐藏密钥值
- 工具调用的参数中敏感值自动打码

---

## 最佳实践

| 建议 | 说明 |
|------|------|
| 生产环境关闭 `allowInsecureAuth` | `control_ui.allowInsecureAuth: false` |
| 公开部署启动速率限制 | 防止 API 盗刷 |
| 启用审计日志 | 定位问题、合规审查 |
| 定期轮换 API Key | 建议 90 天 |
| 使用 `.env` 管理密钥 | 不要将密钥写死在 config.yaml |
| 严格模式配置 deny_commands | 精确到命令名 |
