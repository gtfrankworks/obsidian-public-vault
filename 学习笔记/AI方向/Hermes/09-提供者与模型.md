# 🤖 提供者与模型

Hermes 内置 **25+ LLM 提供者**，开箱即用。

> [!tip] 不一定要全配齐
> 大部分人只用 1-2 个提供者就够了。我的建议是：
> - **主力**：一个便宜快速的（DeepSeek V4 Flash / Gemini 2.0 Flash）——日常对话用它
> - **增强**：一个能力强的（GPT-4o / Claude Sonnet 4）——复杂推理换它
> 
> 配合[[03-配置详解#提供者路由——不同任务走不同模型|模型路由]]，全自动按任务切换，不用手动换。

### 配置示例

```yaml
providers:
  openai:
    api_key: "sk-xxxx"
    default_model: gpt-4o
    max_retries: 3
    timeout: 60

  anthropic:
    api_key: "sk-ant-xxxx"
    default_model: claude-sonnet-4-20250514

  openrouter:
    api_key: "sk-or-xxxx"
    default_model: anthropic/claude-sonnet-4
```

> [!tip] OpenRouter 是「万能钥匙」
> 一个 Key 能访问几乎所有主流模型（包括 Claude、GPT、开源模型）。适合不想注册多家、或者想快速切换对比场景。

## 自托管提供者

如果你有自己的 GPU 或者想用本地模型：

| 提供者 | 配置 key | 说明 |
|--------|---------|------|
| **Ollama** | `ollama` | 最易用，自动下载模型 |
| **vLLM** | `vllm` | 高性能推理，PagedAttention |
| **SGLang** | `sglang` | 前端语言优化，RadixAttention |
| **llama.cpp** | `llama.cpp` | GGUF 格式，低资源 |
| **LiteLLM** | `litellm` | 统一接口 + 负载均衡 |
| **LocalAI** | `localai` | 类 OpenAI API |
| **TabbyAPI** | `tabbyapi` | ExLlamaV2 推理 |
| **KoboldCPP** | `koboldcpp` | 故事创作优化 |

### Ollama 配置

上手最容易：

```bash
# 安装
brew install ollama
ollama pull llama3.2

# config.yaml
providers:
  ollama:
    base_url: "http://localhost:11434"
    api_key: "not-needed"
    default_model: llama3.2
```

### vLLM 配置

需要 GPU，适合生产：

```bash
# 启动
vllm serve mistralai/Mistral-7B-Instruct-v0.3

# config.yaml
providers:
  vllm:
    base_url: "http://localhost:8000"
    api_key: "not-needed"    # vLLM 不验证
    default_model: mistralai/Mistral-7B-Instruct-v0.3
```

### SGLang 配置

```bash
# 启动
python -m sglang.launch_server --model meta-llama/Llama-3.1-8B-Instruct --port 30000

# config.yaml
providers:
  sglang:
    base_url: "http://localhost:30000"
    api_key: "not-needed"
```

### llama.cpp 配置

低资源场景（没有 GPU 也能跑）：

```bash
# 启动 server
llama-server -m model.gguf --port 8080

# config.yaml
providers:
  llama.cpp:
    base_url: "http://localhost:8080"
    api_key: "not-needed"
```

> [!tip] 自托管选哪个？
> - **有 GPU、要性能** → vLLM（PagedAttention 显存利用率最高）
> - **追求简单** → Ollama（一个命令搞定）
> - **没有 GPU** → llama.cpp（CPU 也能跑 GGUF）

## 模型路由

根据任务类型自动选择最优模型——**不用手动切的终极方案**：

```yaml
route:
  enabled: true
  rules:
    # 按工具类型路由
    - tool: vision
      provider: openai
      model: gpt-4o
    
    - tool: code_execution
      provider: anthropic
      model: claude-sonnet-4-20250514
    
    # 按内容类型路由
    - content_match: "需要联网搜索"
      provider: perplexity
      model: sonar
    
    # 默认回退
    - default: true
      provider: deepseek
      model: deepseek-v4-flash
```

> [!tip] 路由规则匹配顺序
> 从上到下逐条匹配，命中第一条就执行。`default: true` 必须放最后——它充当兜底。

## Credential Pools（多 Key 轮询）

多个 API Key 自动负载均衡——绕过单个 Key 的速率限制：

```yaml
providers:
  openai:
    credential_pool:
      - api_key: "sk-key1"
        weight: 3
        max_concurrent: 10
      - api_key: "sk-key2"
        weight: 1
        max_concurrent: 5
      - api_key: "sk-key3"
        weight: 2
        max_concurrent: 8
```

| 参数 | 说明 |
|------|------|
| `weight` | 权重，越高被选中概率越大 |
| `max_concurrent` | 该 Key 的最大并发数 |
| 超出并发 | 自动等待，不会直接失败 |

> [!tip] 什么时候需要 Credential Pool？
> OpenAI 免费版每分钟 3 RPM，付费版也有限制。配 2-3 个 Key 分担压力，跑批量任务时明显快很多。

## 提供者比较

### 成本参考

| 模型 | 输入(每M token) | 输出(每M token) | 特点 |
|------|----------------|-----------------|------|
| DeepSeek V4 Flash | ~$0.3 | ~$0.6 | **性价比王**、中文好 |
| GPT-4o | $2.5 | $10 | 综合最强 |
| Claude Sonnet 4 | $3 | $15 | 代码/长上下文 |
| Gemini 2.0 Flash | $0.1 | $0.4 | 免费额度、极速 |
| Groq LLaMA 3.3 | 免费 | 免费 | 适合测试 |

### 延迟对比

| 模型 | 首 token | 适合场景 |
|------|---------|---------|
| DeepSeek V4 Flash | 快 | 日常对话、实时响应 |
| GPT-4o | 中 | 复杂推理 |
| Claude Sonnet 4 | 中偏慢 | 代码、长文档 |
| Groq | 极快 | 测试、流式体验 |

> [!tip] 我的日常配置
> DeepSeek V4 Flash 走主力，路由规则把代码任务丢给 Claude、视觉任务丢给 GPT-4o。一个月跑下来，80% 的请求都走了 DeepSeek，省了不少钱。
