# ⚙️ 配置详解

核心配置文件 `~/.hermes/config.yaml`，YAML 格式。

这篇不按阅读顺序排——**需要查什么就直接跳过去**。每个配置块独立，互不依赖。

> [!tip] 配置加载优先级
> 配置是从上到下合并的：`.env` > `config.yaml` > 默认值。`.env` 里定义的变量会覆盖 `config.yaml` 里同名的字段。
> 
> 所以 API Key 这种敏感信息放 `.env` 里，config.yaml 里留非敏感配置就行。用 `hermes config show` 可以看最终生效的完整配置。

---

## 顶层结构

```yaml
hermes:           # Hermes 自身行为配置
providers:        # LLM 提供者
gateway:          # 消息网关
skills:           # 技能系统
memory:           # 记忆系统
tools:            # 工具系统
cron:             # 定时任务
plugins:          # 插件
logging:          # 日志
```

八个区块，各管各的。哪个用到了再细看，不用全记住。

## hermes（核心配置）

```yaml
hermes:
  persona: |
    你是 Friday，一个智能助手...
  
  # 默认模型
  default_model: deepseek-v4-flash
  
  # 默认提供者
  default_provider: deepseek
  
  # 会话
  session:
    max_turns: 200              # 单会话最大轮次
    auto_title: true            # 自动生成会话标题
    context_window: 128000      # 上下文窗口
    compression:
      enabled: true             # 上下文压缩
      strategy: summary         # summary / truncate / smart
      trigger_at: 80000         # 超过多少 token 触发压缩

  # 系统提示词目录
  system_prompt_dir: ~/.hermes/prompts/
```

> [!tip] `persona` 决定了 AI 的人格
> 改这个字段后，下一条消息就生效——因为提示词每次都是动态组装的，不缓存。想试不同风格的话，随时改、随时看效果。

> [!question] `context_window` 和 `trigger_at` 什么关系？
> `context_window` 是模型的极限（比如 128K），`trigger_at` 是你希望在耗尽之前就触发压缩的阈值（比如 80K）。让 `trigger_at` 小于 `context_window` 是常规操作——别等到杯子满了再倒水。

## providers（提供者）

```yaml
providers:
  deepseek:
    api_key: "sk-xxxx"
    base_url: "https://api.deepseek.com/v1"
    default_model: deepseek-v4-flash
    max_retries: 3
    timeout: 60

  openai:
    api_key: "sk-xxxx"
    default_model: gpt-4o

  # 自托管
  ollama:
    base_url: "http://localhost:11434"
    api_key: "not-needed"
    default_model: llama3
```

### 提供者路由——不同任务走不同模型

```yaml
route:
  enabled: true
  rules:
    # 按模型能力路由
    - tool: vision           # 视觉任务 → 指定模型
      provider: openai
      model: gpt-4o
    - tool: code_execution   # 代码任务
      provider: anthropic
      model: claude-sonnet-4
```

> [!tip] 路由是我最喜欢的功能之一
> 日常对话用便宜的（DeepSeek），遇到视觉问题自动切 GPT-4o，代码重构切 Claude——**全自动，不用手动换模型**。

### Credential Pools（多 Key 负载均衡）

```yaml
providers:
  openai:
    credential_pool:
      - api_key: "sk-key1"
        weight: 3             # 权重，默认1
        max_concurrent: 10    # 最大并发
      - api_key: "sk-key2"
        weight: 1
        max_concurrent: 5
```

> [!tip] 什么时候用这个？
> 单个 API Key 有速率限制（比如 OpenAI 的 TPM 限制），配多个 Key 分散压力。weight 控制流量分配——Key1 权重 3 意味着它收到的请求是 Key2 的三倍。

## gateway（消息网关）

```yaml
gateway:
  # ── 消息平台 ──
  telegram:
    enabled: true
    bot_token: "xxx"
  
  discord:
    enabled: true
    bot_token: "xxx"
    guild_id: "xxx"
  
  slack:
    enabled: true
    bot_token: "xxx"
    signing_secret: "xxx"
  
  wechat:
    enabled: true
    app_id: "xxx"
    app_secret: "xxx"
  
  feishu:
    enabled: true
    app_id: "xxx"
    app_secret: "xxx"
  
  # ── 监控与控制 ──
  control_ui:
    enabled: true
    port: 8642
    allow_insecure_auth: true   # ⚠️ 本地调试方便，生产关闭

  # ── 速率限制 ──
  rate_limit:
    enabled: true
    max_messages_per_minute: 30
    burst: 10
  
  # ── 会话管理 ──
  session:
    timeout: 1800             # 会话超时（秒）
    max_concurrent: 50
  
  # ── 节点配置 ──
  nodes:
    deny_commands: []
    allowed_roles: ["user", "admin"]
```

> [!warning] `allow_insecure_auth` 记得关
> 本地调试开 `true` 很方便，但如果是公开部署，一定要关掉。不然谁拿到你的端口就能调 API。

> [!tip] 每个平台可以单独覆盖全局设置
> 比如全局限速 30 条/分钟，但 Discord 群多人活跃，可以单独调到 60。见 [[04-消息平台集成#多平台统一配置]]。

## tools（工具系统）

```yaml
tools:
  # 沙箱安全
  sandbox: strict          # off / standard / strict
  
  # 超时
  timeout: 60
  
  # 最大工具调用轮数
  max_tool_calls: 50
  
  # 自动包含的工具包
  toolset: default         # default / minimal / full / none
  
  # 自定义工具
  custom_tools_dir: ~/.hermes/tools/
  
  browser:
    headless: true
    timeout: 30000
  
  code_execution:
    enabled: true
    timeout: 300
    docker:
      enabled: false       # 可选 Docker 沙箱
      image: "python:3.11"
```

> [!tip] `toolset` 的三个档位
> - `default` — 大部分场景够用
> - `minimal` — 只保留最基本的文件+终端
> - `full` — 所有工具全开（适合单用户场景）
> 公开服务建议 `default` 起步，按需手动放行。

## skills（技能系统）

```yaml
skills:
  enabled: true
  auto_load: true         # 启动时自动加载匹配技能
  
  # 技能目录
  directories:
    - ~/.hermes/skills/
    - ~/.hermes/plugins/*/skills/
  
  # 匹配规则
  matching:
    strategy: semantic      # keyword / semantic / hybrid
    threshold: 0.7
```

> [!tip] `auto_load + semantic` 是最省心的组合
> 技能会根据你的问题和当前上下文自动匹配，不需要手动指定要看哪个。`threshold: 0.7` 的意思是匹配度超过 70% 才加载，低了就忽略——避免加载不相关的技能浪费上下文。

## memory（记忆系统）

```yaml
memory:
  enabled: true
  long_term: true
  
  stores:
    user:                   # 用户画像
      provider: file
      path: ~/.hermes/memory/user.md
    memory:                 # 通用笔记
      provider: file
      path: ~/.hermes/memory/memory.md
  
  # 记忆管理
  max_memory_items: 100
  dedup: true               # 去重
  auto_consolidate: true    # 自动合并
  consolidation_threshold: 20   # 超过多少条自动合并
```

> [!tip] `auto_consolidate` 防止记忆膨胀
> 每次你通过 memory 工具存的东西都会加到记忆里。存多了上下文会被撑爆。超过 `consolidation_threshold`（20 条）时自动合并，把旧条浓缩成摘要。

## logging（日志）

```yaml
logging:
  level: info              # debug / info / warn / error
  file: ~/.hermes/hermes.log
  max_size: 10MB
  backup_count: 5
  format: json             # text / json
```

> [!tip] 调试时切 `debug`
> 正常情况下 `info` 就够了。出问题时调到 `debug` + `format: json`，日志结构化了方便 grep。

## .env 文件

`~/.hermes/.env` 存放敏感信息（API Key 等），**优先级高于 config.yaml**。

```bash
# API Server
API_SERVER_ENABLED=true
API_SERVER_KEY=my-local-key

# 提供者 API Key（覆盖 config.yaml）
OPENAI_API_KEY=***
ANTHROPIC_API_KEY=***

# 代理
HTTP_PROXY=http://127.0.0.1:7890
HTTPS_PROXY=http://127.0.0.1:7890
```

> [!warning] 密钥别写进 config.yaml
> config.yaml 可能被你不小心提交到 Git 仓库。把 API Key 放 `.env` 里，即使误传也只是暴露一个没用的占位符。**`.env` 记得加 `.gitignore`**。

## 配置验证

```bash
hermes config validate          # 检查语法
hermes config show              # 显示完整配置（隐藏 API Key）
hermes doctor                   # 全面诊断
```

改完配置先跑 `hermes config validate`——语法错了能直接告诉你哪行有问题。
